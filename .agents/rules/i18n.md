# i18n RULE (Uzbek / Russian / English)

## Languages
- Supported locales: `uz` (Latin script, default unless I say otherwise), `ru`, `en`. Ask me before adding Cyrillic Uzbek or other languages.
- Code, comments, variable names, and commit messages are always English. Only user-facing text is translated.

## Implementation
- NEVER hardcode user-facing strings. Use a translation library (next-intl, i18next, or the project's choice) with one JSON file per locale and namespaced keys (e.g. `orders.status.pending`).
- Every new key must be added to ALL locales in the same change. Missing translations must fail the build or be reported.
- Use ICU/plural rules for plurals (Russian has 3+ plural forms; never do `count + " items"`).
- No string concatenation to build sentences. Use placeholders: `"Hello, {name}"`.
- Keep translation keys stable and descriptive. Never use the English text as the key.

## Formatting
- Use `Intl` APIs for dates, times, numbers, currency, and relative time, based on the active locale.
- Currencies: always show the currency explicitly (UZS, USD, RUB). Never assume one currency.
- Time zones: store UTC, display in the user's time zone (default Asia/Tashkent if unknown).
- Phone numbers: store in E.164 format (+998...), display formatted, use an input mask for UZ numbers.

## UI
- Layouts must survive text expansion: Russian is often 20-35% longer than English. No fixed-width buttons or truncated labels.
- Language switcher visible in the header/settings. Persist the choice (cookie/localStorage) and respect browser language on first visit.
- URLs are locale-prefixed (`/uz/...`, `/ru/...`, `/en/...`) for public sites. Add `hreflang`, localized meta tags, and localized sitemap for SEO.
- Fonts must support Latin Extended and Cyrillic (including Uzbek letters: oʻ, gʻ, sh, ch, ng).
- Use the correct apostrophe characters for Uzbek (oʻ, gʻ), not random quote marks.

## Translation quality
- Translations must sound natural and professional, not machine-literal. For business/customer-facing text, flag anything I should review with a native speaker.
- Keep tone consistent across languages (formal "siz" form in Uzbek, "вы" in Russian).
